# 健身热点研究

本仓库以 Codex 为执行者，ego 为唯一浏览器，WebUI 为本地研究界面。代码中没有无人值守的浏览器服务。读取仓库 `shared/schema.ts` 了解数据契约，采集细节见 [采集约定](references/collection.md)，分析标准见 [分析约定](references/analysis.md)。

## 开始与恢复

- 以仓库根目录为工作目录。读 `data/config.json`，不存在时使用 `shared/schema.ts` 的 defaultConfig。研究方向为健身、运动健康、体态分析、减脂减肥、增肌，默认每日各平台 Top 50，发布时间近7天。
- 先读当前安装的 ego-browser Skill 并运行 `ego-browser skill`。整个任务使用一个 TaskSpace，保存并复用其 ID。没有登录时交还用户；不换浏览器、不提取 Cookie、不导出凭证。
- 查 `data/requests/*.json`、当天 `data/runs/*.json`、`data/risk-state.json`。优先恢复未完成进度，不因每日定时触发而重复翻页或重复打开已采完内容。
- 新建批次用 `pnpm collect:init YYYY-MM-DD`。把打印的 ID 写入本次日志，再执行 `pnpm collect:lock acquire <runId>` 取得独占锁后才能开始采集。若锁已存在，停止并报告；不自动删锁，只有确认原任务结束且用户明确要求恢复时才释放旧锁。正常结束、blocked 或交还浏览器前执行 `pnpm collect:lock release <runId>`；有待执行请求时将其 status 设为 running、绑定 runId。原始 DOM 文本及快照放 `data/raw/<runId>/`，素材放 `data/assets/<runId>/<platform>/<platformId>/`。

## 账号风险边界（优先于数量目标）

低频操作也不能保证账号安全。100条是采集目标，不是必须突破平台限制完成的配额。

- 仅用账号正常可见的页面；只读，不点赞、关注、收藏、发帖、发评论、私信或下单。不换代理、指纹、账号，不绕过验证码、登录、付费或访问限制，不调用未公开接口，不逆向签名。
- 串行执行，同一时间只操作一个平台；禁止并发浏览器、多个采集任务、后台请求批量灌接口。同一仓库的人工请求与定时任务不得同时采集。
- 每次打开新的详情页前，在 ego Node 环境导入 `scripts/risk-budget.mjs` 并调用 `reserveDetail(<绝对data目录>, platform)`。返回 allowed=false 时禁止导航；retryAfterMs 是剩余等待时间，按不超过60秒的多次等待执行，等待结束仍需重新申请。该脚本保存跨批次日限额：总计100、各平台50，详情间隔至少30秒、每10页休息至少3分钟。不因平台切换、批次切换或失败而重置预算。
- 搜索翻页、展开评论、切换评论排序也串行缓慢操作，不把详情页间隔当作允许密集请求的理由。两次滚动至少3秒，每次只滚动一个可见屏幕。评论每条最多12次加载操作；连续2次无新增就停止。取不到时记录缺口。
- 首次看到验证码、异常登录、访问频繁、账号受限、403/429或页面明确风控提示：立即停止该平台的全部操作，保存已采数据，调用 `blockPlatform` 写入原因，把批次/请求标为 blocked。需要人工操作时调用 ego 的 handOff 并明确告知用户；不要自动重试或定时反复打开。其他平台也仅在无需争用浏览器控制权且正常可用时继续。
- 下次定时运行发现 blocked 标记，只报告已有阻塞，不打开该平台。仅在用户明确表示已处理并要求恢复后，清除对应平台标记，继续原进度。不得自行延时解封。
- 普通加载失败最多等待一次明确加载状态后重试一次；仍失败则记缺口并跳过。不得不停刷新、无限滚动或增设关键词追求凑满50。建议用户使用可承受风险的研究账号，但不要替用户注册或切换账号。

## 每日执行

1. 搜索配置的关键词，显式设置“近N天发布”“最多点赞/点赞最多”，记录平台实际支持的筛选条件、搜索URL、候选数和停止原因。不要把抖音热点宝的热度榜或增量点赞榜当作累计高赞榜；如仅能访问这类来源，记录为候选来源，再到详情确认累计点赞。
2. 每关键词最多配置的 candidatePerKeyword 条，跨词按 `platform:platformId` 去重。依平台可见累计点赞数分别排序，选前50。相对发布时间转换为可确认的 publishedAt；日期无法确认的保留为候选，不纳入每日榜。条数不足保留实际数量，明确这是“搜索候选池 Top50”，不是平台全站榜。
3. 在预算内依次打开入选详情，保存标题、作者、来源、发布时间、计数原文及数值、完整正文、内容观察。缺失用 null，不写0；累计和增量必须区分。平台不给的曝光、完播、投流信息不猜测。
4. 视频先播放观察，再在实际时长范围内采关键帧：开头、问题/铺垫、动作/方法、结果、结尾。图文逐页观察并截取关键页。默认5帧，可用 `scripts/ego-tools.mjs` 的 captureVideoFrames；这是对页面中可播放视频定位截图，不下载远端视频、不绕过播放限制。使用 view_image 实际看图后再写 caption、observed、内容分类及结构，未看的画面不得分析。裁切到主体区域；封面不能冒充视频内帧，页面截图 kind=page_capture。
5. 采热评默认50条，若界面支持最新评论再取20条，展开有需求或争议的楼中楼。保留平台评论ID；缺失用稳定 hash，去重并保留父子关系、作者身份、点赞、原始文本和采集时间。标记推广、邀请码、重复营销，不把它们当真实需求。不要采头像、用户主页、私信、手机号等无关信息。无法切换排序或未达数量如实记录。
6. 按分析约定给出内容类型、多选主题、目标受众（内容定位，不推断实际观众性别）、标题钩子、结构、传播假设、评论需求及证据ID。证据不足时 analysis.status=partial，不用模板套写“爆火原因”。
7. 每处理一条保存 run JSON 检查点。用 `pnpm collect:import /绝对路径/run.json` 导入，脚本执行契约校验、素材路径检查、累计点赞排序与去重。对已有数据只追加观察，不改写历史日期的指标快照。
8. 汇总本批次内容模式、用户问题、可做的选题与产品机会；附样本局限，不把评论观点当健康事实。运行 `pnpm collect:finalize <runId>` 更新完成状态与请求；partial/blocked 也必须保存。最后结束 ego TaskSpace（人工交接时不 finish），告诉用户实际完成数量、缺口和本地批次ID。

## 手动与定时

示例：“使用 $fitness-hot-topics 执行今天的采集，保留风险上限，写入本地研究库。”

每天由 Codex 自动化调用本 Skill。不要在仓库额外装系统 cron、常驻抓取服务或 GitHub Actions；云端执行通常没有本机 ego 登录态。自动化无法登录或无法接管时标记阻塞并通知用户，不尝试伪造浏览器环境。调度与本机运行状态独立，WebUI 的“新建采集”仅写入请求；不要宣称已开始执行。

数据、原始评论、登录态和截帧仅保留本地，不随代码提交、推送。用户要求分享数据时再按其指定范围导出。
