# 分析约定

## 内容与画面

多选主题：健身、运动健康、体态分析、减脂减肥、增肌。
内容主类型：动作教学、跟练课程、知识科普、身材展示、减脂记录、体态纠正、测评推荐、运动娱乐、励志故事、商业推广、求助讨论、未分类。标题无法确认实际形式时先未分类。

分别记录 format=video/image_note/text_note/unknown。audience 写内容明确针对的人群，如力量训练新手、久坐人群、产后恢复需求者；没有观众后台就不写“女性观众占比”等推断。

summary 用实际观察概括内容；structure 按实际时间段或图文页记录，引用对应 frameIds。封面、标题、正文、视频画面分开观察。实际没看到声音、字幕或结果，不补写。

## 传播假设

每条给1～3个有证据的假设即可：例如身份共鸣、反差、低门槛方案、可收藏清单、争议或分享用途。每个包含 title/explanation/evidenceIds/confidence/alternative。

high 指“相关内容特征有充分可见证据”，不是“已证明算法因果”。互动绝对值高不证明自然流量、完播高、转粉好。没有曝光量不能算互动率；只有采集评论时不能声称“80%用户想要”。收藏/点赞可计算为两项计数的比值，不能称为收藏转化率或用户人数比。

## 评论与需求

需求须绑定具体 commentIds，保留原话、异议和使用场景。每条评论多标签：动作学习、训练计划、饮食管理、数据记录、复盘进步、体态自查、时间成本、器械适配、价格付费、激励坚持、身体不适、产品兼容、其他。不是所有评论都有需求；赞美、表情、跟风分别对待。

广告、邀请码、互助领会员、开发者引流、重复话术标记 isPromotion，作者回复 isAuthor，不能合计为独立用户需求证据。原帖作者表达可以在 report 中列为“发帖诉求”，不要伪装成评论样本。

优先级 P0：具体使用障碍，有直接用户证据；P1：有场景和原话支持的改进；P2：零散期待或待验证方向。优先级是研究者判断，不等于市场排名。别因一个需求常见而编造引用，也不要把多个回复当成多个独立用户。

分析中保存：原话 -> 痛点 -> 当前替代做法 -> 产品/内容机会。notes/机会可以提出推断，但需标清是建议。周复盘按不同内容的去重评论计数、实际采样条数说明，不重复计算连续多天采到的同一评论。

## 健康表达

不把帖子/评论中的减肥、体态或疾病观点当作已证实事实；产品需求研究不需要替用户诊断。显著的“局部减脂”“运动治病”“极端节食”等主张写 healthClaims 待核实。需要给出医学结论时另查可靠来源，而非靠点赞数或博主身份背书。

## 日结

report.summary 一句话；findings 写3～5条有依据的内容趋势或问题；opportunities 写可执行选题/产品验证建议；limitations 列本轮缺口（筛选不支持、登录/风控、采样偏差、缺曝光或完整视频、评论推广污染等）。每日窗口可能重叠，累计数据不是当日增量，不声称一天爆火。
