# App 调研（重点小红书）

仅通过 ego-browser 做公开可见页面的定向产品研究，沿用主 Skill 的锁、低频访问预算及风控即停规则。不要为新增调研增加账号访问上限。

## 范围

读取 config.appResearch；旧 config 没有此字段时，使用 shared/schema.ts 的 appResearchConfigSchema 默认值。默认开启，近30天，主流产品与独立开发者两组各10条。主流观察清单初始为 Keep、薄荷健康、训记、练练健身，可由用户在采集设置编辑；这不是经过核实的市场排名，不把所有对象称为行业头部。若需要更新头部名单，依据近期可核实的榜单并记录来源，而非凭印象。

检索既覆盖“App名+吐槽/会员/推荐/对比/手表/AI/记录/导出”，也覆盖“独立开发 健身app”“我做了个健身app”“AI健身app”。独立产品必须有原帖或产品页明确的作者身份依据，不因小众、低赞或带邀请码就归为独立开发者。

对比不同帖子来源：用户反馈、开发者发布、产品对比、求推荐、官方更新、其他。主流/独立归属未知时标 unknown，不填猜测。开发者发布保留作为产品动态，发帖人自述不算独立用户验证。

## 去重与批次

- 任何导航之前检查 data/runs 下全部批次，按 platform:platformId 建全局索引。一个 App 帖子只属于一个原始批次，不跨天或关键词重复计入新收集数量。
- 每次选样优先续读尚未读完的原帖。再次打开用于续读不算新帖子，仍计入当日详情访问预算；评论按平台commentId去重，保留 parentId，缺ID使用稳定文本hash并说明可能合并同文评论。
- 对新帖子创建 `pnpm collect:init YYYY-MM-DD app_research`，track=app_research；对旧帖子直接在索引中的原批次追加新评论、更新读取进度，不能复制到新批次。保存前保留原有评论和分析证据，不覆盖为仅本页评论。
- saveRun 会拒绝 App 帖子跨批次重复；同批次仍按平台ID去重。发现拒绝时回到原批次处理，不换ID绕过。
- 仅新增帖属于当前采样目标；续读进度单独报告。新帖不足、归属未知、超预算都写明缺口。App 两组按可见累计点赞排序，保留无点赞显示但具有真实反馈的候选；不将低赞等同无价值。

## 评论必须逐条读完当前可见部分

不以50或70条结束 App 研究。热评排序用于找到问题，之后按平台实际支持的排序与滚动继续读取，展开可访问的全部楼中楼，直到明确出现末尾或无更多内容的可核实状态。

- 串行，每次滚动至少间隔5秒，每次只滚一屏；展开回复也至少间隔5秒。每20次评论加载操作休息至少3分钟；单轮最多20次加载，保存最后评论ID、已读数量与断点，下轮回到原批次续读。
- “单轮操作上限”只意味着本轮暂停，不能将状态写成已读完。连续两次无新增仅代表加载停滞，除非明确看到末尾，仍标 partial、stopReason=加载停滞。
- 各帖子默认评论条数仅作为统计，不是阅读停止条件。页面显示数含隐藏/删除/折叠或限制时，无法证明所有评论均可访问；写清“当前可见已读完”，不要宣称平台全部评论读完。
- commentSampling.readStatus=partial（待续读）、all_visible（确认可见末尾且可展开回复已读）、blocked（验证或限流）。resumeCursor 保存最后确认位置；stopReason 写明末尾、预算休息、加载停滞或平台限制。expandedReplies 如实填写。
- 首次风控即停，写平台 blocked 标记。不要因为用户要求“全部看完”自动重试或绕过验证。后续只在用户确认处理后恢复。

## 数据标记与分析

每条 item.researchTrack=app_research，appResearch：
- appNames：实际提到的产品名，多产品对比可多选；不知道就空数组。
- productGroup：mainstream / indie / unknown，含义为观察分组，不是排名。
- postType：用户反馈 / 开发者发布 / 产品对比 / 求推荐 / 官方更新 / 其他。
- dimensions：功能诉求、会员价格、手表同步、训练记录、饮食记录、数据导出、AI效果、留存障碍、使用门槛、兼容性、隐私等实际出现的维度。
- classificationEvidence：分组与身份依据，保存原话或来源说明。

重点输出“用户在什么情景遇到什么问题、目前怎么替代、愿意付费的条件、作者承诺与用户反馈是否一致”。needs 只引用非作者且非推广的真实评论。产品发布数据与用户反馈分开统计；邀请码、互助会员、开发者引流不计需求人数。未知活跃用户、收入、下载量不推断；个别吐槽不代表产品整体质量。

创建独立 App 调研批次时只选择小红书，窗口使用 appResearch.windowDays、每组数量用 postsPerGroup；rankItems 负责分组排序。快照、评论和实际读取的画面仍按既有数据契约保存。本批次评论未达到 all_visible 时必须 partial，即使帖子数已达标。

## 每日运行

appResearch.enabled=true 时，将此调研加入每日流程，优先续读待完成评论，再分配新帖。与普通内容采集共用50条小红书详情、100条总详情日预算，不在两个流程各申请一份。可优先 App 研究，余量用于普通内容；普通内容不足目标如实记录。自动化再次触发不得重置预算或重复帖子。
