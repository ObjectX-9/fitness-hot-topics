# Wan 动作讲解视频

把动作内容转成可看清操作过程的讲解视频。复用本次已采用的工具链，先用 genImage 生成动作分镜，再把实际图片绑定给 Wan 3.0，最后完成解说、字幕与剪辑。写提示词、生成片段、制作整片的执行范围按用户当次要求确定。

## 确定输入与范围

- 从当前聊天提取动作主题、参考视频、画幅、目标时长、讲解语言和用户已选视觉方案。继续已有任务时读取对应资产索引、提示词与采用记录，复用已有素材和云端任务。
- 有参考视频时实际查看关键帧与动作过程，记录动作顺序、机位切换、字幕内容和声音安排。已有 rea-video 报告可直接读取相关章节，缺少分析时才使用可用的 rea-video 技能。
- 用户允许自行定内容时，围绕一个清楚主题安排必要动作。人物外形默认采用用户已选的 **猫头教练 B「棱面雕塑」**，以 [图片资产索引](assets/资产.json) 的 `canonicalLook` 为准。保持灰白哑光材质、猫科头部、成年健身人形与灰短裤，人物自身左裤腿前外侧印包内 Fitness Cat Logo，全身无尾巴、无毛色花纹。Logo保留用户原图配色，其余角色保持灰白。场景、器械和肌群高亮按当前动作安排，用户新的外观选择优先。
- 新创作按实际动作过程组织时长。同类视频保留需要的讲解结构。完整复刻另建原片到成片的时间映射，逐项核对漏镜、动作和字幕。
- 仅要求总结技能、分析、分镜或提示词时交付对应内容。用户要求制作视频时按当次授权生成。默认先做一个代表片段供确认，已明确授权整段制作时按该范围推进。

## 动作与讲解先对齐

用户要求优先找高质量真人动作参考再生成。先读取 [专业动作与真人视频参考](references/professional-motion-references.md)，按当前动作检索专业机构的动作库和教学原片，实际审看完整动作周期，再选取清楚的真人片段约束动作轨迹与节奏。包内猫头教练图负责身份、服装与Logo，真人片段负责动作，已选音频负责音色；将参考实际绑定进生成请求并记录来源、截取时段与职责。仅有网页说明或单张图时如实记录，不能写成已用真人动作数据。

为每个动作建立一条记录，包含动作名称、讲解文案、起止时间、景别机位、动作阶段、身体支撑、器械接触、参考职责和字幕重点。

按讲解内容拆镜后分别生成：每镜只承担一个操作阶段，讲到下放时下放、讲到停顿时已到达底部、讲到推起时推起。按信息选择能看清支撑、轨迹或关节的机位，不把整段固定在同一侧面。审看各镜后再剪辑；不依赖一次长视频请求自行实现全部切镜和口播同步。

动作阶段至少能表达起始姿势、发力移动、末端停顿和受控回落。根据实际需要选择全身、侧面、背面或局部镜头，确保关节和器械运动方向可读。近景用于补充细节，全身镜头交代支撑与空间关系。

解说按画面发生的顺序写，动作名、操作要点和提示出现的时间相互对应。健身内容区分可见动作、设计的肌群提示和需要专业依据的训练建议。次数、组数与功效沿用用户已选材料或有依据的方案。

## genImage 分镜

先读取 [参考图目录](references/reference-images.md) 与 [图片资产索引](assets/资产.json)，实际查看默认人物图 `assets/reference-images/cat-coach-B.png`，并将它传入生图工具锁定人物外形。另附 21 张动作分镜，覆盖胸、背、肩、手臂、臀腿与腹部，按需参考动作构图、器械布局和姿态；这些图已替换为用户采用的同一猫头教练；保持人物身份、灰色短裤与左裤腿 Fitness Cat 印花。Logo原图见资产索引，按需传入，随布料透视与遮挡呈现。S08、S14、S16等动作阶段与原姿态参考有变化，使用前按当前讲解核对。逐张记录参考职责，并核对当前工具的参考数量限制。

1. 调用当前环境的 genImage／imagegen。先完成并审看所需分镜图，再提交使用这些图片的 Wan 任务。保存每张图的最终中文提示词。
2. 一张图只表达一个可见瞬间。明确镜头角度、身体朝向、关节姿态、双手握持、脚底支撑、器械结构和接触阴影。跨镜保持人物比例、服装、器械形态、场景与灯光。
   动作姿态、器械方向和机位透视优先来自实际审看的真人关键帧，猫角色图只锁外形。必要时同时提供真实顶端与底部姿态，先纠正分镜几何再生成视频。卧推特别检查杠铃横跨身体左右、与头脚长轴的三维关系，避免纯侧面躯干配上沿头脚方向的错误杠轴。
3. 提示词按六节组织，依次为「景别与构图」「人物与姿态」「环境与道具」「光线与色彩」「材质与成像」「画面要求」。画幅与实际参考绑定另记参数。
4. 肌群高亮贴合身体表面，限定区域和颜色。需要准确位置或时间的文字、勾叉、轨迹线和图卡放到后期制作。底图默认无字幕、无额外文字、无水印；保留用户指定的裤腿 Fitness Cat Logo及其字样，不增加其他品牌。
5. 查看实际图片，核对姿态、握持、服装、器械和高亮位置，修正影响动作理解的问题后再用于视频。记录实际使用的图片路径与职责。

在有角色资产管理的项目中遵守该项目现行引用规则。动作演示使用用户选定的演示主体。采用本项目角色时读取对应 active 资产和锁定音色。

## Wan 3.0 生成

优先沿用当前已可用的媒体生成入口。项目已有 Toonflow 入口时使用它，无法使用时在已有授权和配置范围内调用百炼。实际工具字段、模型能力、参考上限和允许时长按当前接口核实。

- 将分镜图实际传入模型，明确每张图负责的人物外观、服装、姿态或机位。文字中提到图片时同步核对请求中的绑定顺序。
- 一次生成尽量围绕一个动作周期或清晰的小组动作。多动作章节写明每段局部起止时间、动作与硬切位置，生成后逐项核对模型实际采用的顺序和时码。
- 中文提示词把景别、机位和运镜放前面，再写动作发生过程、身体与器械接触、光线材质、声音和结束状态。用具体运动描述控制速度，发力、停顿和回落分别安排。
- 人物、手脚、哑铃和杠铃数量固定。脚底、凳面、膝部等支撑持续接触，拉索始终连通，手掌保持握持。服装、器械和人体在切镜后延续选定外观。
- 默认启用原生声音。无人偶对白的动作演示可以使用画外解说，明确人偶保持无口部、无对口型。有关节或器械声时按动作发生安排。
- 清晰写出无字幕、无额外文字、无 OSD、无水印，保留裤腿 Fitness Cat 印花及其字样，随裤腿运动、透视与遮挡保持一致。参考视频已有字幕和图卡时也要求移除，并在成片中检查是否残留。
- 参考视频只在当前接口支持且任务允许时传入，职责写清动作、构图或节奏。本项目禁止使用的亦恬片继续遵守禁用规则。

本次接口限制与输入示例见 [Wan 接入与制作案例](references/wan-case.md)。该记录只说明曾跑通的条件，实际调用先核对当前能力。

## 声音与后期

- 动作讲解默认使用用户已选的 **05 · 男声A「明亮利落」**。读取 [默认音色索引](assets/voices/默认音色.json)，使用包内 `assets/voices/05_男声A_明亮利落.mp3` 作音色参考。新的声音选择与项目既有角色音色要求优先。
- Wan 有声制作将该样本按当前接口上传并绑定为 `reference_audio`／`audioReference`，在提示词中指定它负责画外讲解的声音身份，解说原句仍写入提示词。采用首尾帧模式时先核对它能否同时接收音色参考；不兼容时在授权范围内选用可绑定图片与音频的参考素材模式，并记录输入方式。
- 需要以该音色合成新试听时，复用索引中的音色 ID，并使用其绑定的 `qwen-audio-3.1-tts-plus` 模型。跨账号使用前检查该 ID 是否可用；包内试听可作为当前工具支持的声音参考，迁移后保存实际新绑定。视频生成后核对与样本的音色一致性。
- 原创视频默认用 Wan 原生解说，检查是否漏词、改词以及解说与动作是否对应。用户已选音色时沿用可用的锁定参考。
- 用实际生成的解说校准动作时刻，不能把提示词里的秒数当作实际发生时间。可在工具与授权范围内转写词句时间，再与动作起点、底部、推起逐项对照。适度调整画面速度、裁去多余重复或延长真实末端停顿；记录映射与定格区间，不能靠定格或变速掩盖错误姿态。局部重做画面时可沿用已采用的 Wan 原生解说音轨，避免无谓换声；注明实际音轨来源。外部转写遵循当前素材与服务的实际授权，不将一次授权推定为所有后续任务的授权。
- 用户明确要求保留原音轨时，记录源片、截取范围与全片时码。只保留所选音轨，避免与生成片段声音同时播放。独立画外解说按用户选择与项目规则处理。
- 根据实际采用音轨和用户指定文案整理字幕。字幕数据统一维护起止时间、正文、重点词和样式，由同一份数据导出 SRT 与烧录版。
- 黄白字、黑描边、重点词变色可以沿用本次参考风格，位置和字号依据实际画幅检查。肌群图卡、勾叉和轨迹线各自记录时间与位置，跟随身体的图形需要随动作移动。
- 原片图卡复用需要任务允许且记录具体区域与时段。避免与生成视频残留图卡重复叠加。
- FFmpeg 有字幕能力时直接使用。缺少 libass 或 drawtext 时可用 Pillow 生成透明文字层，再按时间叠加。字体从本机可用项选择，记录真实字体与字号。
- 各段统一分辨率、帧率、像素格式和音频参数。按实际视频切点映射讲解与字幕，必要时先分动作裁切，再做小幅时长调整。
- 完整成片从第一帧覆盖到末句。保留无字幕版、字幕版和字幕数据，渲染到临时文件，完成后再替换目标版本。

## 云端任务与断点续作

提交成功后立即保存 task_id、组号、请求参数、提示词路径、参考路径和提交时间。每次状态变化回写索引，下载成功后记录本地路径。保存索引时使用临时文件加原子替换，避免进程中断留下半份记录。

重启时优先检查已完成文件和已有 task_id。排队、超时、连接中断或终端失去会话后先查询原任务。提交结果不明确时，通过可用任务查询结合提交时间和可获得的请求信息恢复归属，确认后再继续。只有确认失败或取消后，才按原授权考虑重试，保留失败原因与新旧任务关联。

参数错误先修正参数。相同错误再次发生或重试将扩大费用、时长与制作范围时，报告具体阻塞并等待新的决定。进程仍在运行时先核查它负责的章节，避免重复提交同一段。

长任务持续检查云端状态、下载和合成进程。仅在章节完成、发生错误或需要用户选择时更新。用户要片段时优先展示已有可播放结果，并说明是否已有解说、字幕及可见偏差。

## 验收与交付

抽查关键姿态和动作过渡，核对动作顺序、接触受力、器械结构、服装连续性、图卡残留与跨镜一致性。检查解说、字幕和画面的同步，以及时长、分辨率、音轨、首尾完整性。受用户验证限制时遵从并说明未检查项。

资产索引至少关联动作分镜、提示词、实际参考、任务 ID、生成片段、音轨来源、字幕数据、最终成片和审看结论。采用状态依据用户实际选择记录。

交付可播放视频与需要的文件链接，简短说明实际完成范围、声音来源、自行确定的视觉选择和仍存在的偏差。区分设计目标、实际观察与用户采用结果。
