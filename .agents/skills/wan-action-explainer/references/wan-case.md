## 百炼直接调用

本次 Toonflow 服务不可用，直接使用本机已有百炼配置。配置位于 `/Users/zhuling/Documents/zaodian/Toonflow-app/data/settings.json`，读取 `settings.mediaProviderConfigs.bailianMedia`。实际接口根据配置的 workspaceId 确定。密钥只在请求时使用。

请求使用 `POST /services/aigc/video-generation/video-synthesis`，异步头为 `X-DashScope-Async`，值为 `enable`。从 `output.task_id` 取得任务 ID，以 `GET /tasks/{task_id}` 查询。`SUCCEEDED` 后从 `output.video_url` 下载，失败时记录返回的错误码和消息。

本次已成功返回视频的请求结构如下。媒体 URL 中省略的内容需要替换为当前接口支持的真实资源 URL 或 data URL。

```json
{
  "model": "wan3.0-video",
  "input": {
    "prompt": "已保存的完整中文动作提示词",
    "media": [
      {"type": "reference_image", "url": "图片资源"},
      {"type": "reference_video", "url": "动作参考视频资源"}
    ]
  },
  "parameters": {
    "prompt_extend": false,
    "duration": 26,
    "resolution": "1080P",
    "ratio": "9:16",
    "audio": true,
    "watermark": false
  }
}
```

Toonflow 封装入口使用 `generateAudio`，本次直接调用百炼的请求使用 `parameters.audio`。字段对应关系根据所用入口处理。

## 本次观察到的限制

- 首次参考视频总时长 25.5 秒被拒绝，错误提示上限为 15 秒。
- 参考压到 14 秒后，26 秒输出仍被拒绝，错误提示输入视频时长与输出时长之和超过 30 秒。
- 后续将 25.5 秒动作参考加速压到约 3 秒，配合 26 秒输出，任务已成功返回。示例采用 `min(14, 29 - 输出秒数)` 作为参考时长预算，为帧取整留出余量。
- 该压缩方式改变动作参考速度。提示词中曾要求恢复正常动作并按各段局部时码切镜，但抽帧仍观察到动作与切镜偏差。后续按目标选择更短的生成单元或更清晰的动作参考，再通过实际结果判断。
- 胸部任务从提交到生成结束约 16 分半钟，背部任务约 14 分钟。这是本次实测等待时间，后续按任务状态判断进度。

当前接口支持范围应在再次制作时查阅官方文档或可用工具说明。

## 动作提示词示例

下面示例用于单动作演示。时长和解说需按实际选题调整。

```text
## 景别与机位
竖屏九比十六，侧前方全身固定机位，完整拍到双脚、双手和两只哑铃。主体保持在画面中部，为下方字幕留出空间。

## 主体与进入状态
沿用参考图中的灰白无脸三维人偶、素面黑色运动短裤和深灰蓝训练空间。人偶站稳，双脚保持接触地面，两只手各握一只哑铃，双臂自然垂于身体两侧。

## 动作过程
先短暂停稳，再由肩部带动双臂向两侧抬起，肘部保持参考图中的轻微弯曲。哑铃随手掌移动，到达选定高度后短暂停顿，再受控下降到起始位置。躯干稳定，双脚不滑动，手掌全程握住哑铃。按镜头时长完成清楚的抬起、停顿和回落。

## 光线与肌群
柔和侧上方主光呈现肩臂体积，脚底有稳定接触阴影。肩部指定肌群局部橙红高亮，边缘带少量紫蓝光，高亮随身体表面移动。

## 声音与结束状态
采用画外解说，人偶保持无口部。说出已经确定的讲解文案，解说与当前动作阶段对应。在双臂回到起始位置后结束。

## 画面要求
双手、双脚与哑铃数量固定，器械无变形，服装一致。无字幕、无额外文字、无图卡、无品牌、无 OSD、无水印。
```
